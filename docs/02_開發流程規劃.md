## 1. 開發生命週期總覽

```
階段0 環境建置與 Spike ─▶ 階段1 需求與設計 ─▶ 階段2 輸入引擎 ─▶ 階段3 鍵盤 UI（仿原生＋主題）
        (1–1.5 週)            (1 週)              (2–3 週)          (4–5 週)
                                                                        │
                                                                        ▼
階段7 維運與迭代 ◀─ 階段6 驗收與安裝 ◀─ 階段5 整合與測試 ◀─ 階段4 輔助選詞與剪貼簿
     (持續)            (0.5 週)            (1–2 週)               (2 週)
```

> **最重要的原則：先打通「Windows → 雲端編譯 → 側載 → 手機上能用」這條管線，並驗證碼表能從主 App 交給鍵盤，再寫功能。**
> 沒有 Mac、免費 Apple ID、碼表不能放進 repo，這三件事的風險都集中在階段 0。

時程以每週約 10–15 小時業餘時間估算，到 v1.0 約 **12–15 週**，v1.1 再加 4 週。

## 2. 各階段工作內容

### 階段 0：環境建置與技術驗證 Spike（約 1–1.5 週）

**目標**：證明整條無 Mac 開發流程可行，並驗證高風險技術點。

| 3.6 | 地球鍵（長按鍵盤清單同原生，iPad 必顯示）、按鍵音、觸覺回饋 | FR-U12, U14, U16 |

> 建議 3.2 開始寫按鍵元件時就透過主題 token 取色，不要先寫死顏色再改，3.10 才不會變成大重構。

**無 Mac 的開發技巧**：
- UI 全部用程式碼撰寫（UIKit 為主，主 App 可用 SwiftUI），不使用 Storyboard / XIB。
- CI 在 iOS 模擬器跑 UI 測試並**截圖上傳 Artifact**，先在 Windows 上比對外觀，確定後再側載實機，減少側載次數。
- 手勢手感（觸控板、長按）只能在實機上調，集中一次側載測多項。

**出口條件（Gate 3）**：所有 MUST 的 UI 與輸入功能在 iPhone + iPad 實機可操作 → **v0.5 Alpha**。

### 階段 5：整合與測試（約 1–2 週）

| 測試類型 | 方式 | 執行環境 |
|---|---|---|
| 單元測試 | XCTest / swift-testing，針對 IMECore（虛構碼表） | Windows 本機 + CI |
| UI 自動化測試 | XCUITest，操作主 App 的測試輸入框 | CI 模擬器（iPhone + iPad） |
| 快照測試 | 各版面 × **各主題** × 深淺色 × 方向截圖比對（swift-snapshot-testing） | CI 模擬器 |
| 主題驗證 | 所有內建主題 JSON 格式驗證、文字 / 背景對比度自動檢查 | Windows 本機 + CI |
| 效能 / 記憶體 | XCTest `measure`、`XCTMemoryMetric`；實機日誌記錄記憶體 | CI + 實機 |
| 冷啟動 / 快打 | 強制結束鍵盤後第一鍵延遲；每秒 10 鍵多指重疊輸入的掉字率（NFR-15、16） | CI（觸控模擬）+ 實機 |
| 備份還原 | 匯出 → 刪除重裝 → 還原，資料一致；舊版資料 migration 測試 | CI + 實機 |
| 隱私檢查 | 確認日誌中無輸入文字 / 剪貼簿內容；剪貼簿過濾規則測試 | CI + 實機 |
| 手動驗收 | 第 6.2 節清單 | 實機 |
| 長時間測試 | 連續打字 10 分鐘 | 實機 |

**出口條件（Gate 5）**：無 P1 / P2 缺陷、記憶體 < 30 MB。

### 階段 7：維運與迭代（持續）

- 免費 Apple ID：每 7 天重簽（Sideloadly 手動 / AltStore 自動）；重簽是否保留資料由 Spike 0.16 確認；無論結果，皆有自動備份與一鍵還原（FR-D04、D05）。重簽時務必沿用相同 Bundle ID（風險 R13、R14）。
- iOS 大版本更新後跑一次手動測試清單。
- 依使用心得新增 Issue，1–2 週一個迭代。

## 3. 建議專案結構

```
ios_輸入法/
├─ docs/                         # 文件
├─ project.yml                   # XcodeGen 專案定義
├─ Packages/
│  └─ IMECore/                   # 純 Swift Package（可在 Windows 測試）
│     ├─ Sources/IMECore/
│     │  ├─ Cin/                 # .cin 解析、建立索引檔
│     │  ├─ Composer/            # 組字狀態機
│     │  ├─ Candidates/          # 候選字查詢
│     │  ├─ Suggestion/          # 常用詞建議
│     │  ├─ Phonetic/            # 同音字、反查字根
│     │  ├─ Kana/                # 羅馬字→假名規則
│     │  └─ English/             # 自動大寫、雙空白句點等規則
│     └─ Tests/IMECoreTests/
│        └─ Fixtures/sample.cin  # 虛構測試碼表（唯一允許進 repo 的 .cin）
├─ App/                          # 主 App
├─ KeyboardExtension/            # 鍵盤擴充（UIInputViewController）
├─ Shared/
│  ├─ KeyboardUI/                # 版面引擎、仿原生按鍵元件、手勢
│  ├─ Layouts/                   # 版面 JSON（iPhone / iPad）
│  ├─ Themes/                    # 內建主題 JSON、主題引擎
│  └─ Storage/                   # App Group 存取、設定、剪貼簿資料
├─ Resources/OpenData/           # 可散布的開源資料（注音、常用詞）
├─ Tools/                        # 資料轉檔、打包 ipa、碼表檢查腳本
├─ UITests/
├─ .github/workflows/
├─ LICENSES/
└─ README.md
```

**依賴方向**：`App` / `KeyboardExtension` → `Shared` → `IMECore`（IMECore 不依賴任何上層）。

## 4. 版本控制與分支策略（GitHub Flow）

| 項目 | 規範 |
|---|---|
| 主分支 | `main`：永遠可編譯、可安裝 |
| 功能分支 | `feature/<issue號>-<簡述>`，如 `feature/12-cin-parser` |
| 修正分支 | `fix/<issue號>-<簡述>` |
| 合併方式 | PR → CI 全綠 → 自我 Review（可用 Claude Code `/code-review`）→ Squash merge |
| Commit 訊息 | Conventional Commits：`feat:`、`fix:`、`test:`、`docs:`、`refactor:`、`ci:` |
| 版本號 | SemVer；Build number 用 CI run number |
| Tag | `v0.1.0`、`v1.0.0`…，打 Tag 觸發 Release |

## 5. CI/CD 流程設計

```
push / PR ─────────▶ [Linux runner] swift test IMECore（快）
                     [Linux runner] 碼表防護檢查：repo 中除 Fixtures/sample.cin 外不得有 *.cin

PR / push 到 main ─▶ [macOS runner]
                       1. xcodegen generate
                       2. xcodebuild test（模擬器：iPhone + iPad）
                       3. 上傳測試報告與 UI 截圖

push tag v* ───────▶ [macOS runner]
                       1. xcodebuild archive（CODE_SIGNING_ALLOWED=NO）
                       2. 打包 Payload/*.app → .ipa
                       3. 檢查 .ipa 內不含 .cin / 碼表資料庫
                       4. 建立 GitHub Release，附上 .ipa

下載 .ipa ─────────▶ Windows: AltServer 以免費 Apple ID 簽章並安裝
```

**Public repo 注意事項**：
- Public repo 使用標準 GitHub-hosted runner 不計分鐘數，macOS 建置不必刻意節省，但仍建議加 `paths` 過濾與快取以縮短等待時間。
- 目前不需要任何簽章 Secrets（免費帳號在 Windows 端簽章）。日後若升級付費帳號，憑證放 GitHub Secrets（`${{ secrets.P12_BASE64 }}` 等），並設定 **Fork 的 PR 不執行需要 Secrets 的 job**。
- `.gitignore` 排除 `*.cin`、`*.p12`、`*.mobileprovision`、`*.ipa`、`.env`。
- **Artifacts 與 Releases 任何人都能下載**，所以 `.ipa` 絕不能含碼表或個人資料。

### 6.3 缺陷分級
| 等級 | 定義 | 處理 |
|---|---|---|
| P1 | 鍵盤閃退、無法輸入、碼表或個資外流 | 立即修正，阻擋發版 |
| P2 | 主要功能錯誤（選字錯、版面破圖、手勢失效） | 當期修正，阻擋發版 |
| P3 | 次要問題、外觀細微差異 | 排入 Backlog |

### 6.4 除錯策略（無 Xcode）
1. 能在 IMECore 重現的問題，一律先寫失敗的單元測試再修（Windows 本機即可）。
2. 鍵盤端使用 `os.Logger`，Windows 上以 `idevicesyslog` 過濾查看。
3. 日誌**只記事件與錯誤，絕不記錄輸入文字與剪貼簿內容**。
4. Crash 報告：「設定 → 隱私權與安全性 → 分析與改進 → 分析資料」。
5. 疑難問題：短期租用雲端 Mac 以 Xcode 連實機除錯。
