共通規則：
- 所有檔案都帶 `schemaVersion`；讀到較新的版本時拒絕寫入、保留原檔（FR-D06）。
- 文字一律 UTF-8；時間一律 ISO 8601（UTC）。
- 寫入採「暫存檔 → 原子性取代」，避免 App 與鍵盤同時寫入造成損毀。
- 使用者輸入內容（常用詞、剪貼簿）只存在裝置本機，**不寫進日誌**（NFR-06）。

## 1. 鍵盤版面 JSON（階段 1.5）

### 1.1 檔案
| 檔案 | 內容 |
|---|---|
| `Shared/Layouts/iphone.json` | iPhone：字母頁、123 頁、#+= 頁 |
| `Shared/Layouts/ipad.json` | iPad：同上，含 Tab、中 / 英切換、收鍵盤、下滑小字 |

版面只描述「有哪些鍵、相對寬度、輸出什麼」；顏色由主題決定（[04_UI規格.md](04_UI規格.md) 第 6 章），實際 pt 尺寸由版面引擎依螢幕寬度計算。

### 1.2 寬度單位與每列切齊
- 每頁以 **unit** 描述按鍵寬度：**字母鍵 = 1 unit**。
- **每一列各自解出自己的 unit**，讓每列在任何螢幕寬度下都左右切齊（各列字母鍵寬相差 < 0.1 pt）：

  `unit = (可用寬度 − 間距 × 間距數) ÷ (按鍵 unit 總和 + 縮排 × 2)`

  間距數 = 按鍵數 − 1 + 縮排 × 2（`inset` 每側外加同比例的間距）；`spacer` 的寬度加在相鄰兩鍵的間距上，不另外多算一個間距。
- 可用寬度 = 容器寬度（有 `contentWidth` 時取兩者較小並置中）− 左右邊距 × 2。
- 驗算（[04_UI規格.md](04_UI規格.md) 量測值）：

| 情境 | 可用寬度 | 邊距 / 間距 | 計算（第 1 列） | 量測 |
|---|---|---|---|---|
| iPhone 直向 | 430 | 6.5 / 6 | (430 − 13 − 54) ÷ 10 = **36.3** | 36.3 |
| iPhone 橫向 | 690（置中） | 0 / 6 | (690 − 54) ÷ 10 = **63.6** | 63.7 |
| iPad 直向 | 834 | 8.6 / 9.4 | (834 − 17.2 − 103.4) ÷ 12.59 = **56.7** | 56.6 |
| iPad 橫向 | 1194 | 14.8 / 13.6 | (1194 − 29.6 − 149.6) ÷ 12.59 = **80.6** | 80.4 |

  自動測試（`LayoutTests`、`IPadLayoutTests`）對照量測值，並在 iPhone 7 種、iPad 11 種寬度下確認每列切齊。

### 1.3 結構

```json
{
  "schemaVersion": 1,
  "device": "iphone",
  "metrics": {
    "portrait":  { "sideMargin": 6.5, "keyGap": 6, "rowGap": 11,  "keyHeight": 45, "topInset": 8, "bottomInset": 4 },
    "landscape": { "sideMargin": 0,   "keyGap": 6, "rowGap": 8.5, "keyHeight": 32, "contentWidth": 690, "topInset": 6, "bottomInset": 4 }
  },
  "pages": {
    "alpha": {
      "rows": [
        { "keys": ["q","w","e","r","t","y","u","i","o","p"] },
        { "inset": 0.5, "keys": ["a","s","d","f","g","h","j","k","l"] },
        { "keys": [
            { "type": "shift", "width": 1.34 },
            { "type": "spacer", "width": 0.24 },
            "z","x","c","v","b","n","m",
            { "type": "spacer", "width": 0.24 },
            { "type": "backspace", "width": 1.35 } ] },
        { "keys": [
            { "type": "page", "target": "numbers", "label": "123", "width": 1.29 },
            { "type": "langToggle", "width": 1.29 },
            { "type": "space", "width": 5.66 },
            { "type": "return", "width": 2.76 } ] }
      ],
      "landscapeRows": [ "…橫向的按鍵寬度比例與直向不同，需要時整份列出" ]
    },
    "numbers": { "rows": [ "..." ] },
    "symbols": { "rows": [ "..." ] }
  },
  "variants": {
    "email": { "alpha": { "3": { "keys": [ "…整列取代第 4 列" ] } } }
  }
}
```

**按鍵寫法**：
- 字串 `"q"`：字元鍵的簡寫，等同 `{ "type": "char", "output": "q" }`。
- 物件：完整欄位如下。

| 欄位 | 說明 |
|---|---|
| `type` | `char`、`shift`、`backspace`、`space`、`return`、`globe`、`emoji`、`page`（切頁）、`langToggle`（中 / 英）、`tab`、`dismiss`（收鍵盤）、`spacer`（只佔位） |
| `output` / `shiftOutput` | 一般 / Shift 時的輸出；`!,` 這類鍵用 `output: ","`、`shiftOutput: "!"`。**只有使用者自己按的 Shift 才會改輸出**，句首自動大寫不會把 `,` 變成 `!` |
| `label` | 鍵帽文字，省略時用 `output` |
| `secondary` | iPad 上方小字與**下滑輸入**的字元（FR-U25，v1.1 實作；目前只存資料） |
| `alternates` | 長按替代字元（FR-U06）；實際由 `AlternateCharacters` 表提供，不必每個鍵寫 |
| `width` | unit 數，預設 1 |
| `target` | `page` 型按鍵要切到的頁 |

**橫向**：`landscapeRows` 省略時橫向沿用 `rows`。

**情境變化**（FR-U10、U11）：`variants` → 變化名稱（`email`、`url`）→ 頁面 → 列編號（字串）→ 取代的**整列**。橫向若有同編號的列也一併取代。數字、電話欄位由控制器直接切到 `numbers` 頁。

**中 / 英切換鍵**：iPhone 的第 4 列以 `langToggle` 取代原生的表情鍵（表情符號改由候選列工具按鈕進入）；iPad 放在原生「注音」鍵的位置，表情鍵放在原生麥克風的位置。

**嘸蝦米模式**：沿用同一份字母頁；設定「鍵帽顯示字根」時，鍵帽文字改用碼表 `%keyname`（FR-A04，尚未實作）。

## 2. 碼表索引檔 `table.idx`（階段 1.6，ADR-01）

由主 App 匯入 `.cin` 時建立，存於 App Group；鍵盤以 memory-map 唯讀開啟。

### 2.1 檔案結構（little-endian）

| 區段 | 內容 |
|---|---|
| Header（80 bytes） | magic `"MYIX"`、`formatVersion: UInt16`、`flags: UInt16`、`codeCount: UInt32`（不重複字根數）、`valueCount: UInt32`（候選總數）、`maxCodeLength: UInt8`、四個區段的 offset / length（UInt32 × 8）、來源檔指紋 16 bytes（App 端填 SHA-256 前 16 bytes）、`extraKeys`（UInt8 數量 + 最多 11 個 ASCII：字根中實際出現的 a–z 以外字元，如 `,` `.`，讓引擎不依賴 `%keyname`） |
| Meta | `ename`、`cname`、`selkey`、`%keyname` 對照（UInt16 長度前綴 UTF-8） |
| Codes | 依字根 bytes 排序的固定 16 bytes 紀錄：`code[8]`（ASCII，不足補 0）、`valueStart: UInt32`（第一個候選的編號）、`valueCount: UInt16`、保留 2 bytes |
| Values | 位移表（每個候選一個 UInt32）＋字串池（UInt16 長度前綴 UTF-8，相同字串只存一次）；同一字根的候選編號連續、**依碼表原始順序**（FR-K05） |
| Reverse | 8 bytes 紀錄：`valueIndex: UInt32`、`codeIndex: UInt32`；依「字 bytes → 字根長度 → 字根」排序，反查時短碼在前（FR-S07） |
| Footer | CRC32（IEEE，涵蓋 footer 之前所有 bytes） |

實作：`IMECore/Table/TableIndexFormat.swift`（版面）、`TableIndexBuilder.swift`（建立）、`TableIndex.swift`（查詢）。

- 字根上限 8 bytes：實測最長 5 碼（含假名 `,` `.`），保留餘裕。
- 同一字根多個候選（重碼）在 Values 連續存放，查詢一次取完。
- 前綴查詢（萬用字元 FR-K11、預覽）用二分搜尋找起訖範圍。
- 同一字根下完全相同的候選只保留第一個。
- 大小估計：26,283 筆約 Codes 0.4 MB、Values 0.3 MB、Reverse 0.2 MB，總計約 1 MB（3 萬筆測試的上限設為 1.5 MB）。

### 2.2 驗證與重建
- 載入時一定檢查 magic、`formatVersion`、區段範圍；CRC32 預設也檢查，不符就提示使用者重新匯入（不嘗試修復）。
- **鍵盤冷啟動略過 CRC32**（`verifyChecksum: false`），避免啟動時掃過整個檔案（NFR-15）；主 App 在匯入時與每次啟動時完整驗證，異常時提示重新匯入。
- `formatVersion` 升版時，主 App 啟動會用保留的 `.cin` 副本自動重建索引。
- `.cin` 原檔副本與索引都只在 App Group，**不進備份**（FR-D05、R-LIU-1）。

## 3. 使用者資料（App Group，JSON）

| 檔案 | 內容 | 寫入方 | 上限 |
|---|---|---|---|
| `settings.json` | 設定（FR-A04 等） | App | — |
| `phrases.json` | 常用詞記錄與自訂詞（FR-S02） | 鍵盤、App | 5,000 筆 |
| `clipboard.json` | 剪貼簿歷史（FR-C01~C05） | 鍵盤 | 預設 20 筆 / 7 天 |
| `themes/<id>.json` | 自訂主題（FR-T06） | App | — |
| `table_meta.json` | 已匯入碼表的名稱、筆數、匯入時間、來源檔名 | App | — |

### 3.1 `settings.json`

```json
{
  "schemaVersion": 1,
  "keySound": true,
  "haptics": true,
  "autoCapitalize": true,
  "doubleSpacePeriod": true,
  "spaceSwipeUpEnglish": true,
  "spaceSwipeUpAppendSpace": false,
  "autoCapitalizeEnglishSend": true,
  "fullWidthPunctuation": true,
  "numberRow": false,
  "keycapLabel": "letter",
  "composingDisplay": "bar",
  "candidateCount": 0,
  "phraseLearning": true,
  "clipboard": { "enabled": true, "maxItems": 20, "maxDays": 7 },
  "theme": { "id": "native", "appearance": "system" },
  "backup": { "enabled": true, "keep": 10 }
}
```

- `keycapLabel`：`letter`（英文字母）/ `radical`（碼表字根標籤）。
- `composingDisplay`：`bar`（鍵盤上方，預設）/ `inline`（輸入框游標處，FR-K13）。
- `candidateCount`：0 表示依寬度自動。
- `theme.appearance`：`system`（跟隨系統，預設）/ `light` / `dark`；App 指定的 `keyboardAppearance` 優先（FR-U23）。
- 鍵盤每次 `viewWillAppear` 重新讀取；缺欄位用預設值；檔案比 App 新時只讀不寫（`SettingsStore`）。

### 3.2 `phrases.json`

```json
{
  "schemaVersion": 1,
  "items": [
    { "text": "信義", "count": 12, "lastUsed": "2026-11-10T08:00:00Z", "source": "learned" },
    { "text": "嘸蝦米", "count": 0, "lastUsed": null, "source": "manual" }
  ]
}
```

- `source`：`learned`（連續送出的字自動記錄）/ `manual`（使用者手動新增，不會被淘汰）。
- 排序分數 = `count` × 時間衰減（30 天半衰期）；超過上限時淘汰分數最低的 `learned`。
- **只影響聯想建議，不影響碼表候選順序**（FR-S03）。
- 設定關閉 `phraseLearning` 時停止記錄，既有資料保留到使用者清除。

### 3.3 `clipboard.json`

```json
{
  "schemaVersion": 1,
  "items": [
    { "id": "UUID", "text": "…", "createdAt": "2026-11-10T08:00:00Z", "pinned": false }
  ]
}
```

- 只在**使用者按下剪貼簿按鈕**時讀取系統剪貼簿並記錄（Spike 0.10：iOS 每次讀取都會跳「允許貼上」，R7）。
- 符合 OTP、信用卡號、長串無空白英數等格式時**不記錄**（FR-C04）。
- 去重：與最新一筆相同時只更新時間。

## 5. 備份檔（FR-D04、D05）

單一 JSON 檔：`MyIME-backup-YYYYMMDD-HHmm.json`

```json
{
  "schemaVersion": 1,
  "app": "MyIME",
  "appVersion": "1.0.0",
  "createdAt": "2026-11-10T08:00:00Z",
  "settings": { },
  "phrases":  { },
  "clipboardPinned": [ ],
  "themes": [ ],
  "tableHint": { "name": "嘸蝦米", "sourceFileName": "liu.cin", "importedAt": "..." }
}
```

- `settings` / `phrases` 為對應檔案的完整內容；`clipboardPinned` 只含釘選項目；`themes` 為自訂主題陣列。
- **不含碼表**，只有 `tableHint` 提醒使用者重新匯入哪個檔（R-LIU-1）。
- 未釘選的剪貼簿項目不備份（可能含敏感內容）。
- 自動備份保留最近 `backup.keep` 份；還原時逐區段驗證，任一區段失敗就略過該區段並提示，不覆蓋現有資料。

## 6. 版本與 migration（FR-D06）

| 狀況 | 處理 |
|---|---|
| 檔案 `schemaVersion` < 目前版本 | 依序執行 migration（v1 → v2 → …），成功後才覆寫；原檔另存 `.bak` |
| 檔案 `schemaVersion` > 目前版本 | 唯讀使用可辨識的欄位，**不寫入**，提示更新 App |
| JSON 解析失敗 | 保留原檔改名 `.corrupt`，以預設值啟動並提示可從備份還原 |
